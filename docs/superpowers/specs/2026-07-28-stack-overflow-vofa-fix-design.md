# MSPM0 VOFA 速度异常值修复设计

## 问题证据

- 左右编码器累计计数正常。
- 异常速度 `4375344267319684873226027008.0f` 的 IEEE-754 位模式为
  `0x6D623333`，按小端字节解释为 ASCII `33 33 62 6D`（`"33bm"`）。
- Keil 链接器报告当前最大栈使用量为 336 字节，且仍有无法静态追踪的调用；
  启动文件实际只分配了 256 字节栈。
- 链接布局中 `vofa_senddata[]` 紧邻栈底。栈向低地址溢出时会优先覆盖
  VOFA 发送数组，因此可能出现编码器变量正常、VOFA 曲线值异常的现象。

## 修改方案

将 `startup/startup_mspm0g350x_uvision.s` 中的 `Stack_Size` 从
`0x00000100`（256 字节）增大为 `0x00000800`（2048 字节）。

本次不修改：

- 右轮 TIMG8 QEI 配置、启动、读取和计数逻辑；
- 左右轮编码器计数与 RPM 换算公式；
- PID 参数和电机方向；
- VOFA 通道内容与 JustFloat 协议。

## 验证

1. 重新执行 Keil 全量构建，要求 0 errors、0 warnings。
2. 检查新的链接图，要求 `STACK` 段大小为 2048 字节。
3. 检查链接器报告的最大栈使用量，确认其小于分配的 2048 字节。
4. 检查 Git 差异，确认没有改动右轮 QEI 代码。
5. 上板后同时观察 `motor_left_speed_fdb`、`motor_right_speed_fdb` 和
   `vofa_senddata[0..1]`，确认不再出现 ASCII 位模式对应的异常巨值。
