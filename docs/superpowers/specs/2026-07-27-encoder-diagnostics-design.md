# 编码器计数诊断设计

## 当前物理与代码映射

- 物理左轮对应代码中的 `QEI_ENCODER_RIGHT`、`motor_right_encoder_count` 和
  `motor_right_speed_fdb`，使用 TIMG8 硬件 QEI，目前工作正常。
- 物理右轮对应代码中的 `CAPTURE_ENCODER_LEFT`、`motor_left_encoder_count` 和
  `motor_left_speed_fdb`，使用 TIMG7 双通道捕获和软件 AB 解码，目前计数为 0。

本轮诊断保持现有代码命名，避免在根因未确认前影响电机方向、闭环控制和 VOFA
通道含义。最终修复时再统一物理左右映射。

## 诊断方案

在 `motor_inf_task.c/.h` 中增加 `volatile` 诊断变量：

- TIMG7 ISR 总进入次数、CC0/CC1 分支命中次数。
- TIMG7 最后一次中断索引以及未处理索引次数。
- 软件 AB 解码器最近的前态、现态和增量。
- 有效跳变、无效跳变、同态采样次数。
- TIMG8 硬件 QEI 最近的原始计数和增量，作为正常侧对照。

诊断代码只观察和计数，不改变捕获配置、编码器累计值、速度公式或电机输出。

## 验证

由于真实定时器捕获输入依赖开发板和编码器，本次经用户同意采用 Keil Watch
实机验证。烧录后分别转动物理左右轮，根据诊断变量判断故障位于中断索引、
单通道捕获、AB 状态读取还是软件解码。构建用于确认新增变量和代码能够通过
ARM 编译器检查。

## 已确认根因与修复设计

实机诊断结果为：TIMG7 ISR 3032 次，CC0 1515 次，CC1 1517 次，
未处理 IIDX 为 0，但 3032 次 AB 采样全部为同态 `00 -> 00`。这证明
TIMG7 双通道捕获正常，故障位于通过 GPIO DIN 读取外设复用引脚状态。

修复继续使用 TIMG7：

1. 复位编码器状态时停止 TIMG7，并在临界区内短暂把 PA17/PA18 配置为
   GPIO 数字输入，读取一次真实 AB 初态。
2. 立即恢复 PA17/PA18 的 TIMG7_CCP0/CCP1 外设输入功能，清除切换期间
   的捕获中断状态，再重新启动 TIMG7。
3. 运行期间 CC0 捕获事件表示 A 发生一次边沿，因此翻转软件状态的 A 位；
   CC1 捕获事件同理翻转 B 位。软件状态随后交给现有四倍频查表解码器。
4. 初始化阶段电机停止、轮子保持静止，避免引脚复用切换窗口内发生边沿。
